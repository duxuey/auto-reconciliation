## 1. 背景与目标

会议纪要明确了再保对账的实际流程：

1. **系统间校验**：承保、理赔分别与再保核对（对条数、对金额）；承保取**核保通过时间**，理赔取**核赔通过时间**。
2. **出账前精算核对**：再保与精算/准备金核对「分出保费清单」「分出已决清单」；人民币口径；合同号 `OP` 开头为分入转分出，业务号位置使用账单号；单笔尾差不超过 1 元；分出类型不看自留，自留部分不加总。
3. **再保出账**：核对通过后由再保系统出账（本系统只做闸门放行，不执行出账）。
4. **出账后全辖核对**：对清精算数据后汇总全辖，与财务核对，输出财务报表清单。

《自动对账指标》目录已把第 1 步和「再保送收付 ↔ 收付账单」落实为可执行的 SQL 指标：承保临分分入 11 项、理赔主表 11 项、非车共保 9 项、临分分入理赔 11 项、险别赔款/费用 3 项、收付与再保 3 项。

本系统的目标：

- 把这些 SQL 指标升级为**配置化、可版本化、可审计、可钻取**的自动对账平台；
- 覆盖「指标定义 → 执行时直连抽取 → 执行 → 指标汇总 → 差异明细 → 差异处理 → 阶段闸门 → 报表」完整闭环；
- 输出口径与现有 SQL 完全对齐，并以 SQL 作为验收对拍基线；
- 独立部署，不修改 `ri-service` / `ri-web`。

## 2. 范围与边界

### 2.1 在范围内

- 系统间：承保 ↔ 再保、理赔 ↔ 再保、再保送收付 ↔ 收付账单。
- 指标包/版本、数据集接入（**生产默认只读读库**）、执行批次、指标结果、差异明细、差异处理、调整建议、系统间闸门、报表导出。
- 文件导入保留为样例与兜底通道。
- 数据量暂不限制（`MAX_RUN_ROWS=0`），后续通过配置管控。

### 2.2 不在范围内

- **精算/准备金、财务全辖对账**（2026-10-29 明确不做）。
- **`承保与再保（旧）` 目录指标**（不使用旧口径；综合合并包暂不实施）。
- **与 `ri-web` 集成**（后续集成到新核心系统，本期不接菜单/SSO/iframe）。
- 银行流水对账、总账/会计凭证、账务记账。
- 再保出账操作本身（由 `ri-service` 执行，本系统只提供放行/阻断信号）。
- 修改 `ri-service` / `ri-web` 的代码、表结构或菜单。
- 理赔核赔、承保核保、收付执行等业务处理。
- 多租户隔离与权限体系（保留 `tenant_id`、`x-actor` 审计，SSO 后续接入）。
- 用户自定义 SQL 指标（明确禁止，见 §9.3）。

## 3. 总体设计

### 3.1 架构

```
源系统（只读）                        自动对账系统（独立新工程）
┌────────────────────────┐           ┌─────────────────────────────────────┐
│ 临分分入承保 fpic_ifac_db│           │ apps/api  @infra/biz-reconciliation │
│ 理赔        fpic_clm_db │           │  ├─ REST /api/reconciliation/*      │
│ 再保接口    fpic_ri_risk_db│         │  ├─ tRPC /trpc/*                    │

│ 收付账单    fpic_rp_db  │           │  ├─ 指标引擎（TS + Money）          │
│ 精算/准备金 （待提供）   │           │  ├─ 指标包/版本/闸门/差异闭环       │

                                      └─────────────────────────────────────┘
```

- 收付侧：账单主表 + 明细表；`c_prtc_mark` 空值按 `0`；金额不调方向。
- 金额字段：原币金额、人民币金额。

### 4.8 `RI_ACTUARY` 与 `FIN_SCOPE`（待数据源细化）

**RI_ACTUARY**（出账前）：

- 范围：分出保费清单、分出已决清单。
- 规则：人民币口径；合同号 `OP` 开头时，业务号位置使用账单号；剔除自留，自留不加总；单笔尾差 `abs ≤ 1.00`。
- 指标模板：M001 条数、M002 业务键数、M003 再保有精算无、M004 精算有再保无、M101 金额（容差 1.00）、M102 币种不符。
- 数据源：再保分出清单、精算/准备金清单（库表字段待提供）。

**FIN_SCOPE**（出账后）：

- 范围：全辖再保汇总 ↔ 财务全辖数据。
- 指标模板：M001 条数、M002 业务键数、M003/M004 遗漏/多出、M101 金额、M102 分机构/币种汇总。
- 输出：财务报表清单（分机构、期间、币种、业务类型、金额、差异）。
- 数据源：全辖汇总与财务数据（库表字段待提供）。

## 5. 领域模型与状态机

### 5.1 概念模型

| 概念 | 说明 |
|---|---|
| 指标包 CheckPack | 一组核对指标，绑定阶段（INTERFACE / PRE_BOOKING / POST_BOOKING） |
| 指标包版本 CheckPackVersion | 不可变发布快照：对账组、业务键、指标、过滤/方向/容差 |
| 对账组 Comparison | 包内的一个左右数据集配对，含业务键与指标列表 |
| 数据源数据集 SourceDataset | 逻辑数据集：源系统、抽取方式、字段映射 |
| 导入批次 ImportBatch | 一次文件导入或一次只读抽取同步 |
| 暂存记录 StagingRecord | 归一化记录：业务键 + 动态金额集合 + 元数据 |
| 执行 CheckRun | 指标包 + 期间 + 版本 + 输入清单；FULL / DRY_RUN |
| 指标结果 MetricResult | `metric_code/name/check_result/total_count/fail_count` |
| 差异明细 CheckDiff | 指标级差异：业务键、字段、左值/右值/差异值 |
| 处理流水 DiffLog | 只增不改的差异处理审计 |
| 调整建议 Adjustment | 补收/补付/冲销/数据修正/确认核销 |
| 阶段闸门 CheckGate | 三阶段放行/阻断/签核 |
| 作业 Job | 导入/同步/执行/导出 |

### 5.2 状态机

| 实体 | 流转 |
|---|---|
| 指标包 | DRAFT → ACTIVE → INACTIVE |
| 包版本 | DRAFT → PUBLISHED → RETIRED（发布后不可改） |
| 导入 | PENDING → VALIDATING → LOADED / PARTIAL / FAILED |
| 执行 | PENDING → RUNNING → SUCCEEDED / FAILED；PENDING/RUNNING → CANCELLED |
| 指标结果 | PASS / FAIL（计算即定稿） |
| 差异 | OPEN → ASSIGNED → INVESTIGATING → RESOLVED / WRITTEN_OFF；RESOLVED/WRITTEN_OFF → OPEN |
| 调整 | DRAFT → SUBMITTED → APPROVED / REJECTED；APPROVED → EXPORTED |
| 闸门 | PENDING → PASSED / BLOCKED → SIGNED_OFF（SIGNED_OFF 仅 L3） |
| 作业 | QUEUED → RUNNING → SUCCEEDED / FAILED；QUEUED/RUNNING → CANCELLED |

状态转移集中定义于 `src/domain/status.ts`，非法迁移抛 `*_CONFLICT`（409）。

## 6. 数据库设计

### 6.1 通用约定

- 库：`db_biz_reconciliation`；表前缀：`biz_reconciliation_`。
- 主键：`id varchar(26)` ULID。
- 所有表：`tenant_id`、`created_at/created_by/updated_at/updated_by`、`deleted_at`（`_log` 只保留 created 两列）。
- 金额 `numeric(19,4)`、费率 `numeric(10,6)`、时间 `timestamptz`、业务日期 `date`。
- 金额集合字段：`amounts_ext jsonb`，值为 decimal 字符串，由 Money 校验（≤4 位小数）。
- 业务键：`business_key_text varchar(512)` + `business_key_ext jsonb`，业务键文本用于检索/钻取。

### 6.2 表清单（13 张）

- 单库 Drizzle 事务；跨系统不引入分布式事务。

### 7.4 直连抽取流程（执行时）

1. **严格解析数据源**：环境必须 `ACTIVE`；数据集必须绑定 `systemId`；环境×系统必须有 `ACTIVE` 映射；
   schema 取 `schemaMap[schemaKey] ?? schemaMap.DEFAULT`；`dbHost/dbUser` 非空且密码环境变量已定义。
   严格模式**不回退** `LEGACY_MYSQL_*`，PROD 配置缺失直接失败。
2. **期间半开区间**：SQL 使用 `>= 开始日 AND < 结束日`，调用时止日传 `periodEndDate + 1 天`，
   修复单日 T-1 抽不到数据的问题。
3. **映射与校验**：`mapSourceRecord` 映射后校验 `businessDate` 非空且落在请求期间内，否则计入行错误；
   同一批次出现重复外部主键直接失败（避免 `onConflictDoNothing` 静默丢行）。
4. **批次复用与隔离**：按
   `v1|DIRECT|dataset|profile|mappingHash|数据源指纹|start|end|内容哈希` 生成批次键；
   内容哈希对映射后的规范化行（排除 raw）排序后计算，源库返回顺序不影响复用。
   同内容复用 `LOADED/PARTIAL` 批次；`PENDING/FAILED` 批次原地替换；已被引用的历史批次不被覆盖。
5. **执行批次**：`check_run.input_manifest_ext.batch_ids` 记录本次使用的批次，执行与重放只加载这些批次，
   后续抽取不会污染历史结果与差异来源钻取。
6. **失败语义**：连接/查询错误不创建批次，只返回脱敏提示（不含 host/账号/密码/SQL）；
   全部数据集 0 行记为「源库期间内无数据」；配置错误记为失败，不伪装成无数据。

> 高级模式「数据接入」保留手动读库同步，仅作为预检/补数；不再是工作台与自动对账的前置条件。

## 8. 指标引擎

### 8.1 处理流程

1. 读取指标包版本配置（对账组、左右数据集、业务键、指标、规则）。
2. 按期间与本次执行声明的批次（`manifest.batchIds`）加载暂存记录；直连数据集在创建批次前已完成抽取。
3. 归一化：空值统一、`trim/upper`、币种/业务来源过滤、金额方向、`claim_type=4` 互换取负、账单期对齐。
4. 按业务键聚合：记录数、金额字段 Money 求和、汇率取最大值。
5. 应用零金额剔除与例外规则。
6. 逐指标计算 `total_count / fail_count / check_result`。
7. 生成差异明细（仅不通过项；缺失类输出两侧键）。
8. 汇总包级结果并更新阶段闸门。

### 8.2 指标类型与计算口径

| 类型 | total_count | fail_count | 差异明细 |
|---|---|---|---|
| `ROW_COUNT` | `max(左行数, 右行数)` | `abs(右行数 - 左行数)` | 不正确时输出两侧行数 |
| `KEY_COUNT` | `max(左键数, 右键数)` | `abs(右键数 - 左键数)` | 输出两侧键数 |
| `MISSING_LEFT` | 左键数 | 左有右无的键数 | 每个缺失键一行 |
| `MISSING_RIGHT` | 右键数 | 右有左无的键数 | 每个缺失键一行 |
| `MISSING_BOTH` | 左键数 + 右键数 | 左缺失数 + 右缺失数 | 缺失键 + 方向 |
| `RECORD_COUNT_PER_KEY` | 两侧均存在的键数 | 记录数不一致的键数 | 键 + 左右记录数 |
| `DUPLICATE_LEFT` | 左键数 | 左侧 `record_cnt > 1` 的键数 | 键 + 记录数 |
| `DUPLICATE_RIGHT` | 右键数 | 右侧 `record_cnt > 1` 的键数 | 键 + 记录数 |
| `SOURCE_ANOMALY` | 命中键数 | 异常键数 | 键 + 来源值 |
| `AMOUNT_FIELDS` | 匹配键数 × 字段数 | 超容差字段数 | 键 + 字段 + 左值/右值/差异 |
| `RATE_FIELD` | 匹配键数 | 超容差键数 | 键 + 左/右汇率 |

### 8.3 容差

- 默认 `amt_tol = 0.00`。
- 精算包 `abs = 1.00`。
- 比较式：`abs(right - left) > tolerance` 即失败。
- 容差可按指标覆盖；执行时可记录一次性覆盖（审计），不改变已发布包版本。

### 8.4 规则配置（示例）

```json

  "checkStage": "INTERFACE",
  "comparisons": [{
    "code": "MAIN",
```

- 每个指标最多 20,000 字符；由指标管理页查看/编辑，新增指标时可一并填写。

  种子按指标代码拆分后写入 `sql`，`pnpm seed` 可完整复现。

### 8.5 确定性与性能

- 分组键排序固定；差异明细按 `metric_code + business_key_text + field_code` 排序。
- 单次执行上限 50 万条/侧；超限拆分期间。
- 批量写入 1000 行/批；目标 10 万条/包 < 60s。
- 金额/汇率只经 Money；日期只经 Time；SQL 不做金额聚合。
- 禁止 `Number` 金额运算、`parseFloat`、`toFixed`、裸 `Date`。

## 9. 安全与规范红线

- 不执行用户自定义 SQL；指标类型为受限枚举。指标配置中的 `sql` 仅为文档/审计说明，任何代码路径不得执行。
  固化在 `apps/api/src/seed/metric-sql/` 的指标 SQL 源文件只含查询文本，不得包含连接凭据。
- 只读抽取 SQL 单库、参数化、登记；禁止跨库 JOIN、动态表名。
- 金额/时间封装在 `packages/engine`；引擎外禁止导入 `decimal.js`/`date-fns`。
- 表名只在 Drizzle schema 字面量出现；查询只经 Drizzle。
- env 集中于 `src/config.ts`；禁止硬编码连接串、服务地址、端口。
- 日志结构化，禁 `console.log`；PII 经 `mask.ts`。
- 所有写操作声明 L1/L2/L3；L3 = dryRun + confirm + 审计。

- `GATE_NOT_FOUND / CONFLICT`

## 17. 规范偏差登记

| 项 | 处理 |
|---|---|
| 新系统 TS 栈 vs 既有 Java/Vue | 按规范 TS 全栈；不修改 ri-service/ri-web |
| 源库跨 schema 取数 | 不跨库 JOIN；单库只读抽取，匹配在 PG/TS 内 |
| 既有指标 SQL | 作为口径事实源与测试基线；运行时不执行跨库 SQL |
| 金额字段动态集合 | `amounts_ext` jsonb（decimal 字符串 + Money 校验），业务键提列，SQL 不做金额聚合 |
| Qa* 裸 SQL 指标 | 不复用；指标类型受限枚举 |
| Keycloak/多租户 | 不实现；tenant_id 由 env 注入；x-actor 审计；SSO 后续 |
| Temporal/禁手写状态机 | 进程内异步 Job 记录 + 集中状态转移表 + 单测；无持久队列/失败重试/水平扩展 |
| L3 审批 | dryRun + confirm + 审计日志 |
| ops/log、OTel | 本地结构化 logger + traceId；Span 织入暂缓 |
| codeGuardian/guard-data | ESLint + repo-lint + 评审兜底 |
| gov/contract | 路由 zod 为源；本地提取器投影 OpenAPI/台账 |
| Money/Time 归 eng/formula | 落 packages/engine |
| 总账/凭证/银行/支付执行 | 不在范围 |
| 精算/准备金、财务全辖对账 | 2026-10-29 明确不在本期范围 |
| ri-web 集成 | 本期不做；后续集成到新核心系统 |
| 生产数据接入 | 默认只读读库；文件导入保留为兜底 |
| 数据量 | 暂不限制（`MAX_RUN_ROWS=0`），后续配置管控 |
| 再保出账 | 外部动作；本系统只做闸门 |
