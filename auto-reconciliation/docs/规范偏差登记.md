## 二、数据与金额/时间

| 项 | 规范要求 | 本项目处理 |
|---|---|---|
| 金额运算 | decimal.js 经 Money 封装 | 已落 `packages/engine/src/money.ts`；引擎外禁用 decimal.js |
| 时间 | Time 封装；禁裸 Date | 已落 `packages/engine/src/time.ts`；UI 展示层按规范 2.4.2 允许在 `apps/web/src/lib/format.ts` 做时区呈现 |
| Money/Time 归属 | eng/formula | 落 `packages/engine`，沿用规范 9.3 的演进路径（未来提升为共享内核） |
| 金额字段动态集合 | 金额字段应提列 | 指标包的金额字段数量随指标变化（2/4/8/16+），采用 `amounts_ext jsonb`（decimal 字符串 + Money 校验）；业务键全部提为 `business_key_text`；SQL 不做金额聚合。属于“动态指标字段集合”登记偏差 |
| 跨库 | 禁跨库 JOIN | 不跨库 JOIN；每个数据集单库抽取/文件导入，匹配在 PG/TS 内完成 |
| 源库直连 | Facade/只读 | **工作台与自动对账执行时按期间直连只读抽取**，无需预先导入/同步；14 个数据集只读抽取 profile 已登记（SQL 集中在 `packages/adapters/legacy-mysql/sql/`），文件导入用于文件数据集/样例/兜底；不直连 ri-service 业务库 |
| 多环境与物理 schema | 连接/库名应集中配置 | 环境（TEST/PROD，可新增 UAT 等）与连接信息存 `biz_reconciliation_environment`；密码只存环境变量名（`db_password_env_key`），运行时经 `readSecret()` 读取，不落库不打印；同一实例下按「环境 × 系统」配置 `schema_map`（如 `{"DEFAULT":"fpic_clm_db","IFAC":"fpic_ifac_db"}`），数据集用 `schema_key` 选择，抽取 SQL 以 `{{schema}}` 占位并由白名单校验；暂存、导入批次、执行、闸门、报表均按 `environment_id` 隔离 |
| 系统对账关系 | 原按指标包隐含 | 新增 `biz_reconciliation_system` 与 `biz_reconciliation_system_pair`（7 个关系）；指标包通过 `pair_id` 归属对账关系，首页与顶栏可切换当前环境/对账关系；未配置指标包的对账关系返回空态而不报错 |
| 同一文件跨环境导入 | 幂等键需区分环境 | 导入幂等键为 `(tenant_id, environment_id, dataset_code, file_hash, mapping_hash)`；执行指纹包含 `environment_id + pair_id`，避免跨环境复用批次或执行结果 |
| 数据量 | 无硬限制 | `MAX_RUN_ROWS=0` 暂不限制；后续通过配置管控。当前引擎为内存分桶，大数据量性能待压测 |

## 三、内核与平台能力缺失（规范 9.3/9.4 模式）

| 规范要求 | 现状 | 过渡方案 |
|---|---|---|
| Keycloak / 多租户 | 未接入 | `tenant_id` 由 env `TENANT_ID` 固定注入；`x-actor` 记录 `user:<id>` / `agent:<id>`；SSO 后续接入 |
| Temporal / 禁手写状态机 | 未接入 | 进程内异步执行 + `job` 记录（jobId 轮询、progress 0/5/100、attempt_count、重启回收 RUNNING→FAILED）+ 集中状态转移表；**无持久队列/SKIP LOCKED/失败重试/水平扩展** |
| L3 审批端点 | 未接入审批系统 | `publish` / `write-off` / `adjustment approve` / `gate sign-off` 采用 `dryRun + confirm + 审计日志`；签核后重跑失败自动回 BLOCKED |
| ops/log 端点 | 不存在 | 本地结构化 logger 薄封装（`{level,service,instant,event,traceId}`），对齐 ops/log 字段 |
| OTel / Tempo | 未接入 | 仅透传 `traceId`（`x-trace-id`）；Span AST 织入暂缓 |
| codeGuardian / guard-data | CI 未建 | ESLint + `repo-lint.ts` + 评审兜底；repo-lint 覆盖表前缀、错误码词表、共享包业务词、SQL SUM/跨库、console/debugger |
| gov/contract 台账 | 未接入 | 路由挂点 zod 为事实源；`contracts:extract` 机械投影 `docs/contracts/openapi.json` 与 `ledger.json`；当前投影含路径、summary、x-governance、错误码，**请求/响应 JSON Schema 投影为 TODO** |
| SeaTunnel ETL | 未接入 | `@adapter/legacy-mysql` 只读抽取 + 文件导入；抽取 SQL 集中在 `packages/adapters/legacy-mysql/sql/` 并登记 |
| 既有指标 SQL 执行 | 规范禁业务裸 SQL | 现有 SQL 作为口径事实源与测试基线，不在运行时执行；生产仅执行登记过的单库抽取 SQL |
| Qa* 数据检核 | ri-service 既有 | 不复用其用户 SQL 指标模型；新系统指标类型为受限枚举，不支持自定义 SQL |
| 再保出账 | 外部动作 | 本系统只提供系统间闸门放行/阻断与留痕，不执行出账 |

## 四、测试与验收

| 项 | 处理 |
|---|---|
| SQL 对拍 | 源 MySQL 业务表未提供，当前采用 `fixtures/expected/seed-summary.json` 快照对拍（`pnpm test:oracle`）；源库就绪后替换为真实 SQL 对拍 |
| 指标覆盖 | 已落系统间 7 包、55 项：UW_RI_FAC 11、CLM_RI_MAIN 11、CLM_RI_COINS 9、CLM_RI_FAC 11、CLM_RI_CVRG 3、RP_RI 3、NB_UW_CLM_GENERIC 7（非车承保↔非车理赔通用指标，待按新核心表结构细化）；精算/财务全辖、旧目录指标、综合包不在本期范围 |
| 新核心承保↔理赔 | 新核心元数据未提供 | 先用通用指标（条数、业务键数、单边缺失、同键记录数、重复、来源异常），表结构就绪后在「环境配置」补 schema 映射与抽取 SQL，再细化金额类指标 |
| 生产读库联调 | 14 个只读抽取 profile 已登记并绑定数据集；执行时严格按「环境×系统」解析数据源（不回退 `LEGACY_MYSQL_*`）；真实 MySQL 字段、过滤条件、跨 schema SELECT 权限与只读账号待联调 |
| 直连无数据/失败语义 | 全部数据集 0 行 → `NO_SOURCE_DATA`（源库期间内无数据）；配置/连接错误 → 失败并返回脱敏原因；单侧有数据仍执行以产生缺失差异 |
| 直连批次复用 | 按内容哈希复用批次：源数据未变化时重复执行复用同一批次/执行，内容变化才生成新批次；每次执行仅加载 `manifest.batch_ids`，保证历史结果与来源钻取不被后续抽取污染 |
| 数据量 | 暂不限制（`MAX_RUN_ROWS=0`）；当前为样例数据，未做大数据压测 |
| 端到端 | Playwright 7 条主链路通过（含按对账关系切换概览/执行/闸门、环境配置页）；差异处理/调整建议的写操作 E2E 尚未覆盖（写操作已由 API 手工验证） |
